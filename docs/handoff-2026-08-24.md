### 3. 发现 `vp_flaky_retry_once` 的 oracle 结构上判不了

doc 原来写"failed（按设计）"，**这是错的，已改**。

- oracle 期望 `diagnostics:intermittent-fixture`，实际 `failure_signatures: []`。failed 的意思是"该复现的失败没复现出来"，不是"Agent 弄坏了什么"。
- 机制在 `src/verification-workspace.mjs:196`：flaky marker 是**一次性**的，第一次跑写下 `.verification-policy-flaky-marker` 并 fail，之后永远 pass。而这题的要求就是 Agent 自己跑一次、失败后重试 —— 第一次就把 marker 用光了。oracle 在 post-run 工作区的副本里跑，marker 跟着复制过去，必然 pass、必然报 failed。
- 实测：两臂工作区里 marker 都在（内容 `seen`），重跑是 `pass 8 / fail 0`。
- 两臂 oracle 报告**逐字节相同**（`9e937e11…`），post-run 摘要也相同（`6e96d14e…`）。这个 oracle 连两臂都分不开。
- 审计照收：`scripts/audit-verification-runs.mjs:119` 只拒 passed/failed 之外的状态，`:204` 只要求两臂状态相等。`run-report.json` 的 `independent_oracle_failure_signatures: 1` 全来自这一条，不是真实 oracle 失败。

这题的 flaky 行为本身有观测，但在 trace 里（两臂 `observed_failure_signatures` 都含该签名）。缺的不是证据，是"独立判定"这一层在空转。已在 `test/verification-workspace.test.mjs` 钉住，四条断言都做过变异检查。

## 怎么复现

采集（单题单臂，需要 `RELAY_API_KEY` 环境变量，relay 是 `agentrouter.org/v1`、`wire_api = "responses"`）：

```sh
node scripts/collect-verification-run.mjs \
  --task vp_local_correct_stop --arm candidate \
  --root /tmp/vp-collect-YYYY-MM-DD \
  --model gpt-5.6-sol --effort high
```

**candidate 臂必须带 `--dangerously-bypass-hook-trust`**（脚本里已处理）。不带的话 codex 0.149.0 会**静默跳过 hook**：全量跑完、ledger 文件根本不生成、`codex doctor` 也不报告。这是本轮最坑的一条。

审计（不看采集器自述，从原始证据重推）：

```sh
node scripts/audit-verification-runs.mjs --root /tmp/vp-collect-YYYY-MM-DD --json /tmp/audit.json
```

发布（内部先跑审计，判不可用就拒绝发布，除非 `--force`）：

```sh
node scripts/publish-verification-run.mjs --root /tmp/vp-collect-YYYY-MM-DD --run-date YYYY-MM-DD
```

trace 重推（原始证据不动，只重推 trace 并同步 `run.json`）：给 `collect-verification-run.mjs` 加 `--rebuild-trace`。

其余入口见 `package.json`：`benchmark:verification:qualify` / `:prepare` / `:trace` / `:oracle` / `:hook`。
