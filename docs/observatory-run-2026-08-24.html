闸门用整串正则、判定按段分解。一条 rg 的搜索模式里出现 pytest 就被认成测试命令，9 段命令词里一个 runner 都没有，于是 fail-closed 拒掉纯查看命令。

oracle 结构性失效
2 次探测均 exit 0
两臂报告逐字节相同 9e937e11

vp_flaky_retry_once 的 flaky marker 是一次性的，被 Agent 必须的第一次运行消耗掉， oracle 在 post-run 副本里必然 pass、必然报 failed。审计器两道关卡都放行了这种恒为 failed 的判定。

独立 oracle 判定

status 是 oracle 自己的判定，workspace_status 是题目预期。 两者不同不等于出错 —— vp_affected_failure 预期工作区失败、oracle 判定 passed，是对的。 六题的两臂 oracle 摘要全部相同，因为五题禁止编辑、Agent 确实一个文件都没改。

不可越的红线
