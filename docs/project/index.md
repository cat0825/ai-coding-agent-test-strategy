## 研究问题

AI 编码代理为什么重复测试、扩大测试、该停不停，浪费从哪个决策点开始。目标不是"少写测试"，
而是让验证路径按风险、反馈速度、可归因性和预算分层。

## 核心主张

1. 编辑阶段优先格式化、lint、类型检查、编译和最小 smoke。
2. 只有回归修复、稳定公共行为变化、共享不变量变化或高风险改动才默认新增测试。
3. 提交阶段执行受影响测试；全量、E2E、mutation、性能测试放到合并或异步阶段。
4. 定向测试失败后最多一次可归因修复和重跑；仍无法归因就停止扩张并报告证据。

默认预算：最多新增 1 个测试文件、最多 2 次即时测试执行、即时测试上限 90 秒。

## 证据纪律

见 `docs/process/boundaries.md`。最硬的一条：效率声明的四个硬门槛写在 issue #17 验收标准里，
任何一条不满足，评估停在 `evidence_insufficient`。
